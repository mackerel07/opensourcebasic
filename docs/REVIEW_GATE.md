# 데이터와 API 사전 검토

저장소 소유자의 요청에 따라 **데이터 구조와 API는 구현하거나 확정 명세로 배포하기 전에 소유자에게 먼저 검토받습니다.** 처음 프론트를 맡는 팀원이 복잡한 서버 설계까지 떠안지 않도록 화면 작업과 실제 연결을 나눕니다.

## 학습 자료 검토

데이터 담당자는 사진 출처, 사용 조건, 예상 수량, 라벨과 분할 계획을 먼저 제안합니다. 저장소 소유자가 승인한 뒤 자료를 수집·정리합니다.

## 아직 결정하지 않은 것

- 실제 Supabase 테이블과 필드, 관계
- 로그인 필요 여부와 누가 어떤 물품·사진을 볼 수 있는지
- 사진 저장 위치, 허용 형식·용량, 업로드 방식
- 서버 API 주소, 요청·응답 형식, 실패와 처리 상태
- SAM2/DINOv2를 실행할 서버와 결과 전달 방식
- 최종 확인 결과를 저장하는 방식

이 문서는 위 항목의 명세나 승인이 아닙니다. 프론트 이슈에 나오는 물품명·수량·샘플 상태는 화면 설계용 예시이며 DB나 API 계약을 확정하지 않습니다.

## 검토는 작게 나눈다

1. 담당자가 먼저 사람이 이해할 수 있는 짧은 안을 준비합니다. “무엇을 저장하는지, 화면이 무엇을 보내고 받는지, 누가 접근하는지”부터 설명합니다.
2. 소유자가 범위를 확인하고 수정 의견을 줍니다.
3. 합의한 범위에 대해서만 필드·요청·응답 예시를 정리합니다.
4. 소유자가 해당 안을 승인한 댓글 또는 문서 링크를 실제 연결 이슈에 남깁니다.
5. 그 뒤 서버 담당자가 구현하고 프론트 담당자가 승인된 약속에 연결합니다.

승인 기록에는 승인자, 날짜, 승인한 안의 링크·버전을 적습니다. 답변이 없거나 PR이 열려 있다는 이유로 승인됐다고 보지 않습니다. 승인 후에도 요청·응답이나 접근 범위를 바꾸면 변경 부분을 다시 검토받습니다.

## 검토 전 진행할 수 있는 것

- Next.js 프로젝트와 페이지 틀
- 임시 목록으로 물품 관리 화면
- 브라우저 사진 선택과 미리보기
- 샘플 분석 상태와 사진 위 영역 표시
- 모바일·키보드·실패 화면 확인

## 검토 전 진행하지 않는 것

- 실제 Supabase 테이블·버킷·권한 변경
- 실제 서버 API의 주소·데이터 구조 확정
- 프론트에 비밀키를 넣거나 권한을 임의로 공개
- 실제 사진 업로드·AI 호출·최종 결과 저장 연결
- 사용자에게 실제 서버 동작처럼 보이는 샘플 성공 처리

이 절차는 소유자가 요청한 협업 조건입니다. 구체적인 서버 선택이나 DB 명세는 별도 검토안을 통해 확인합니다.
