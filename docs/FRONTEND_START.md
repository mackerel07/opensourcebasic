# 프론트 처음 시작하기

## 이번에 만들 화면

물품 관리 → 반납할 물품 선택 → 사진 촬영 또는 파일 선택 → 사진 미리보기 → 분석 상태 → 사진 위 결과 확인 → 사용자 확인 순서입니다.

처음에는 화면과 임시 데이터만 만듭니다. DB, 서버 API, AI 서버를 처음부터 동시에 이해하거나 구현할 필요는 없습니다. 실제 연결은 소유자가 검토한 뒤 담당자와 같이 진행합니다.

## 작업 순서

1. 진행표에서 초기 세팅 이슈를 읽습니다. 공통 화면과 실행 환경부터 준비합니다.
2. 물품 관리 화면을 임시 목록으로 만듭니다.
3. 사진을 고르고 미리보기로 띄웁니다. 이때는 서버 저장이 없어도 됩니다.
4. 샘플 결과로 사진 위 영역·이름을 표시하고 사용자 확인 화면을 만듭니다.
5. 데이터/API 검토가 끝난 뒤 실제 연결 이슈를 진행합니다.

한 번에 한 이슈를 맡고 브랜치와 PR을 만듭니다. [Git 명령과 예시는 CONTRIBUTING.md](../CONTRIBUTING.md)를 봅니다. 각 이슈의 진행 순서·완료 조건·직접 확인할 상황을 체크하면 됩니다.

## 파일과 도구를 쉽게 구분하기

| 이름 | 하는 일 |
|---|---|
| React | 화면의 버튼·목록·입력 같은 부분을 컴포넌트로 만듦 |
| Next.js | 페이지 이동과 웹 앱의 기본 틀을 제공 |
| TypeScript | 코드에서 잘못된 값 사용을 더 일찍 찾도록 도움 |
| npm | 프로젝트에 필요한 라이브러리를 설치하고 실행 |
| mock 또는 임시 데이터 | 서버 없이 화면 동작을 확인하기 위한 예제 |
| API | 화면이 서버에 요청하고 결과를 받는 약속. 아직 확정 전 |
| Supabase | 물품 자료와 사진 등의 관리를 검토 중인 서비스 |
| Vercel Preview | PR 변경을 웹 주소로 확인하는 배포 방식 |

## 폴더는 이렇게 구분할 계획

프론트는 `frontend/`에 둡니다. `src/app`은 페이지, `src/components`는 공통 UI, `src/features`는 기능 화면, `src/mocks`는 샘플, `src/services`는 승인 후 실제 연결 코드입니다. 현재 앱 파일이 이미 생성됐다는 뜻은 아닙니다.

초기 세팅 이슈가 끝나면 `cd frontend`, `npm ci`, `npm run dev`로 실행할 수 있게 합니다. README에 실제 Node/npm 버전과 설치 명령을 적습니다. Next.js의 `npm run build`만으로 린트까지 끝났다고 가정하지 말고 별도 lint·typecheck·test 명령도 확인합니다.

## 막혔을 때 질문하는 방법

이슈 댓글에 다음 네 가지를 적습니다. 민감한 값은 붙이지 않습니다.

1. 어떤 순서로 작업했는지
2. 기대한 화면이나 동작
3. 실제로 나온 화면이나 오류
4. 실행한 명령과 관련 파일

처음부터 완벽한 디자인을 만들기보다, 한 화면을 작게 완성하고 PR에서 함께 확인합니다. 사진 위 영역 표시처럼 어려운 부분은 먼저 사각형 샘플로 동작을 확인합니다.

## 자료와 서버 약속은 먼저 검토

임시 자료를 실제 DB에 그대로 만들거나 임의의 API 주소를 정하지 않습니다. [검토 절차](REVIEW_GATE.md)의 승인 기록이 있어야 실제 연결 이슈를 시작합니다.
