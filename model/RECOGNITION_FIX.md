# 반납 사진 인식 수정 (2026-11-25)

## 원인과 변경

1. SAM2의 전체 가위 마스크가 나와도 `pred_iou_thresh=0.8`, `stability_score_thresh=0.95`에서 탈락했다. 개발용 단독 가위 사진에서 전체 마스크의 값은 약 0.395 / 0.866이었다. 후보 생성 기준을 0.3 / 0.8로 바꾸고, 뒤의 DINO 분류 기준 0.7 / 점수 차이 0.15는 유지했다.
2. 학습의 검증 argmax 정확도가 같은 경우 무조건 C=0.1을 택했다. 이 모델은 검증 정답 11개 모두를 맞혀도 최대 점수가 0.299~0.368이라 실제 추론에서는 전부 거절됐다. 동일 Macro F1에서는 검증 log loss가 낮은 분류기를 선택하도록 바꿨다. 기존 train 39개와 val 11개 특징만 이용했고, 검증 자료로 재학습하지 않았다. 선택된 C는 100이다.
3. 종류를 분류하기 전에 마스크 IoU 0.6으로 제거하면, 품질 점수가 높은 부분 마스크 때문에 전체 물품 마스크가 사라졌다. SAM 내부 상자 NMS와 초기 마스크 제거는 IoU 0.95의 거의 같은 후보에만 적용하고 최대 후보를 128개로 늘렸다. 분류 후 같은 종류의 겹치는 상자를 정리해 손잡이·날을 따로 세는 것을 막는다. 서로 다른 위치의 같은 종류 물품은 유지한다.
4. 후보가 하나도 없으면 물품이 없다고 단정하지 않고 `review`를 반환한다. 불확실한 후보도 사용자 확인을 유지한다.

입력의 EXIF 방향 보정·RGB 변환·크기 축소와 DINO의 회색 배경/224px 여백 전처리는 기존 학습·추론에서 일치했다. 밝기를 일괄 조작하거나 정답 개수에 맞춰 예측을 강제로 채우지 않았다. `expected`는 결과 비교에만 쓰고 후보의 품목·수량 생성에는 사용하지 않는다.

## 재현

기존 SAM2.1 Small / DINOv2 ViT-S/14 및 Python 환경을 그대로 사용한다. 기존 dataset-v1에서 사람 확인을 거친 crop 특징 파일이 필요하다. 자료 준비 과정은 PR #24의 TRAIN_PLAN.md에 있다. 가중치와 원본 사진은 Git에 넣지 않는다.

```bash
cd model
.venv/bin/python train_head.py fit --features /path/to/features.npz --outdir runs/recognition_fix/model
.venv/bin/python -m unittest test_core -q
.venv/bin/python infer_scene.py --image /path/to/photo.jpg --runtime runtime.local.json --classifier runs/recognition_fix/model/head.joblib --device cpu --outdir runs/check-new
```

모델 서버의 로컬 설정 `MODEL_CLASSIFIER`를 새 head.joblib 경로로 바꾸고 서버를 다시 켠다. `inference_config.json`도 이 변경본을 함께 사용한다. 기존 모델 API 키와 Vercel 라우팅은 유지한다.

## 확인 범위

첨부된 return_01~12 사진과 저장소의 반납 정답표를 비교한다. 이 사진들은 원인 분석과 후보 정리 설정 조정에 사용했으므로 **개발 회귀 검사**다. 새로운 환경에 대한 독립 시험 정확도로 해석하지 않는다. 분류기 자체의 적합에는 이 12장이나 파생 crop을 넣지 않았다. 새 물품·배경·더 심한 가림에 대한 별도 촬영 검증은 필요하다.

사진별 개수·상태·실행시간은 recognition_regression.csv에 기록한다. 불확실한 장면의 `review`는 자동 확정 성공에 포함하지 않는다.

## 이번 실행 결과

- 기존 crop 검증 11/11의 argmax 정답은 유지했다. 기존 자동 확정 기준을 통과하는 crop은 0/11에서 11/11이 됐다. 최저 최고점은 0.906, 최저 점수 차이는 0.837이다. 이 점수는 보정된 정답 확률이 아니다.
- 첨부 반납 사진 12장의 세 품목 개수는 모두 정답표와 일치했다. 상태는 complete 1장, missing 3장, review 8장이다. 이 값은 각 품목 1개씩을 정상 기준으로 두고 집계했다.
- review 8장은 수량 추정이 맞았어도 불확실한 후보 또는 예상보다 많은 물품이 있어 사용자 확인을 유지한 결과다. 따라서 12/12를 자동 확정 정확도라고 부르면 안 된다.
- CPU 추론 시간은 사진당 약 6~8초다. HTTP 전송·모델 로드 시간은 이 수치에 포함하지 않았다.
- 원래 실패했던 벌린 가위 1개(return_09), 겹친 가위 2개(return_10), 미등록 물품만 있는 장면(return_12)도 수량이 일치했다.
- 학습/검증 crop 특징과 반납 사진을 구분했다. 이번에 사용한 반납 사진은 이후 독립 평가 자료로 재사용하지 않는다.
